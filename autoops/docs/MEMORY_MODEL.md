# MEMORY MODEL

## Overview

The memory system stores historical knowledge for every monitored service.

Unlike the runtime state, memory is persistent and survives engine restarts.

The memory is stored in:

```
autoops/data/memory.json
```

Each monitored service has its own memory entry.

---

## Purpose

The memory layer allows AutoOps to:

- Remember previous incidents.
- Track recovery history.
- Build service reputation.
- Detect long-term behavior.
- Improve future decisions.

The pipeline updates the memory after every execution cycle.

---

## Memory Structure

Example:

{
    "nginx": {

        "incidents": [],

        "reputation_score": 1.0,

        "total_failures": 0,

        "total_restarts": 0,

        "total_recoveries": 0,

        "risk_history": [],

        "modes": []
    }
}

---

## Incidents

Stores previously detected incidents.

Generated by:

```
classifier.py
```

Only the latest incidents are kept.

Maximum history:

20 entries.

---

## Reputation Score

Represents the long-term reliability of a service.

Updated by:

```
reputation_engine.py
```

Higher values indicate a healthier service history.

---

## Total Failures

Accumulates all detected failures.

Updated from:

```
state.fail_count
```

This value is never reset automatically.

---

## Total Restarts

Stores the total number of recovery attempts.

Updated from:

```
state.restart_attempts
```

---

## Total Recoveries

Stores successful recoveries.

Updated from:

```
state.success_count
```

---

## Risk History

Stores previous calculated risk levels.

Example:

LOW

HIGH

CRITICAL

Only the latest twenty entries are preserved.

This history allows future analysis of service stability.

---

## Mode History

Stores previously calculated operating modes.

Possible values include:

- NORMAL

- RECOVERING

- UNSTABLE

- CRITICAL

Only the latest twenty entries are stored.

---

## Memory Update Process

Memory is updated during every pipeline cycle.

The update sequence is:

State

↓

Decision

↓

Execution

↓

Memory Update

↓

Save memory.json

---

## Memory Handler

The pipeline calls:

```
memory_update_handler()
```

which internally invokes:

```
update_memory()
```

The update process safely initializes missing fields before modifying them.

---

## Persistence

Memory survives:

- Engine restart

- Service restart

- System reboot

It is only lost if:

- memory.json is deleted.

- memory.json becomes corrupted.

---

## Current Limitations

The current implementation stores historical information only.

It does not yet perform:

- Statistical learning

- Trend analysis

- Long-term prediction

- Automatic profile adaptation

These capabilities may be added in future versions.
