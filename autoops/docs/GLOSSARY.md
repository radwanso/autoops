# GLOSSARY

## Overview

This document defines the terminology used throughout the AutoOps project.

These definitions provide a common vocabulary for developers, maintainers, and contributors.

---

## Action

An operation executed by the system in response to a decision.

Examples:

- Restart
- Escalate

---

## Behavior

An evaluation of how a service has been behaving based on recent failures and configured thresholds.

Generated by:

```
behavior.py
```

---

## Brain

The central interface that exposes the system's intelligence modules.

The Brain does not implement the logic itself.

Instead, it provides a unified entry point to all analysis components.

---

## Cognitive State

A high-level summary describing the current operational condition of a service.

Generated before the final decision is made.

---

## Configuration Profile

A collection of service-specific settings loaded from:

```
config/config.yaml
```

Profiles define thresholds, cooldowns, criticality, and recovery behaviour.

---

## Decision

The final action selected by the Decision Engine.

Typical values include:

- OBSERVE
- RESTART
- ESCALATE
- STABLE

---

## Engine

The main execution loop of AutoOps.

It coordinates the monitoring cycle and invokes the Pipeline for each configured service.

---

## Event

A message exchanged between system components through the Event Bus.

Events allow modules to communicate without direct dependencies.

---

## Event Bus

The internal communication mechanism used to connect independent modules.

Handlers subscribe to events and return processing results.

---

## Event Analysis

Analysis of historical service events.

Used by prediction and intelligence components.

---

## Execution

The stage responsible for performing recovery actions.

Examples:

- Restart service
- Escalate incident

---

## Experience

A measurement derived from historical service behaviour.

Used as one of the intelligence inputs.

---

## Incident

A classified operational problem detected during analysis.

Produced by:

```
classifier.py
```

---

## Memory

Persistent historical information maintained for every monitored service.

Stored in:

```
data/memory.json
```

---

## Metrics

Current system measurements collected during each execution cycle.

Examples include:

- CPU usage
- Memory usage
- Disk usage

---

## Mode

The current operational condition of a monitored service.

Possible values include:

- NORMAL
- RECOVERING
- UNSTABLE
- CRITICAL

---

## Pipeline

The sequence of processing stages executed for each monitored service.

The Pipeline performs analysis, decision making, execution, and memory updates.

---

## Policy

Rules that determine whether specific recovery actions are allowed.

Generated before the Decision Layer.

---

## Prediction

An estimation of future service behaviour.

Generated by the Prediction Engine.

---

## Profile

The runtime configuration assigned to an individual monitored service.

Loaded from:

```
config.yaml
```

---

## Recovery

Any action intended to restore a failed service.

Recovery may include restarting a service or escalating the incident.

---

## Reputation

A long-term reliability score maintained for every service.

Calculated from historical operational behaviour.

---

## Response Plan

A structured description of the actions recommended before execution.

Generated during the Strategy Layer.

---

## Risk

The calculated severity level assigned to a service.

Possible values:

- LOW
- HIGH
- CRITICAL

---

## Safe Emit

A protected wrapper around the Event Bus.

It executes event handlers safely and returns default values if errors occur.

---

## Service

A monitored operating system service managed by AutoOps.

Examples:

- nginx
- cron
- ssh

---

## State

The complete runtime representation of a monitored service.

Stored in:

```
data/state.json
```

---

## Strategy

The operational approach selected before making a decision.

Examples include observation or recovery strategies.

---

## System State

The global operational status of the AutoOps environment.

Stored inside:

```
_system
```

within:

```
state.json
```

---

## Task

A recovery request created for later execution.

Tasks represent pending operational work.

---

## Timeline

A chronological sequence of events and completed recovery actions.

Displayed by the Web Dashboard.

---

## Runtime

The active execution period while the Engine is running.

Runtime information exists only during execution and is refreshed every cycle.
