# AutoOps State Schema

## Overview

The state object is the central data structure used throughout AutoOps.

Every engine reads from it, updates it, and passes it to the next stage of the pipeline.

A complete and valid state object is required for the system to operate correctly.

---

# Basic Structure

Example:

```json
{
  "service": "nginx",
  "status": "UP",
  "fail_count": 0,
  "restart_attempts": 1,
  "success_count": 1,
  "history": [],
  "mode": "NORMAL",
  "behavior": {},
  "incident": {},
  "risk": {},
  "prediction": {},
  "strategy": "OBSERVE",
  "policy": {},
  "decision": "OBSERVE",
  "profile": {},
  "metrics": {}
}
```

---

# Field Description

## service

Service name.

Example:

```
nginx
```

---

## status

Current service status.

Possible values:

- UP
- DOWN

---

## fail_count

Number of consecutive failures detected.

Used by:

- Behavior Engine
- Risk Engine
- Decision Engine
- Mode Engine
- Memory Engine

---

## restart_attempts

Number of restart attempts performed.

Used to determine whether recovery should continue or escalate.

---

## success_count

Number of successful recoveries.

Used for calculating recovery effectiveness and operating mode.

---

## history

List of historical events related to the service.

Used by:

- Event Analysis
- Pattern Detection
- Prediction

---

## metrics

Current system metrics collected during the execution cycle.

Typically includes:

- CPU usage
- Memory usage
- Disk usage

---

## profile

Service-specific configuration loaded from config.yaml.

Contains thresholds and recovery limits.

---

## behavior

Behavior analysis generated by the Behavior Engine.

Example:

```json
{
  "unstable": false,
  "safe_to_restart": true
}
```

---

## incident

Classification of the current incident.

Generated by the Incident Classifier.

---

## risk

Current calculated risk.

Example:

```json
{
  "level": "LOW"
}
```

Possible values include:

- LOW
- HIGH
- CRITICAL

---

## mode

Current operating mode of the service.

Possible values:

- NORMAL
- RECOVERING
- UNSTABLE
- CRITICAL

---

## prediction

Failure prediction generated by the Prediction Engine.

Example:

```json
{
  "will_fail": false,
  "confidence": 0.82
}
```

---

## strategy

Selected operating strategy.

Examples:

- OBSERVE
- RECOVER
- ESCALATE

---

## policy

Recovery policy generated for the current state.

Determines whether recovery operations are permitted.

---

## decision

Final decision produced by the Decision Engine.

Examples:

- STABLE
- OBSERVE
- RESTART
- ESCALATE

---

# State Ownership

The state object is shared across all engines.

Every engine should only modify the fields that belong to its responsibility.

No engine should overwrite unrelated sections.

---

# Persistence

The current state is persisted in:

```
autoops/data/state.json
```

The state file represents the latest known status of every monitored service.
